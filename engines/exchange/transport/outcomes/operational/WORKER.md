# M06.12c.1 — Explicit recovery worker (test only)

Run `Test-ExchangeOperationalWorker.ps1` from the repo. Existing native V4 executable and `quantdesk_test` required. Do not run concurrently with other database tests. The same fixture schema lifecycle as the validated operational flow is used. No runtime application wiring, no permanent migration.

Each step holds the existing cooperative flow lock. It reads the journal at the persistent cursor, looks up the durable local command and receipt, checks the decision against delivery, records it, applies idempotent M07 effects, then advances the cursor. Unknown or unconfirmed journal commands stop the worker. The default worker never sends new commands; explicitly enabling `resumePreparedTestCommands` dispatches only ready fixture intents when journal delivery is drained. Pending submissions are never auto-reserved. Each pass is bounded; the loop delays between passes and stops on cancellation or failure. An operator must explicitly restart after inspecting a failure; no auto-reset or automatic release on unknown outcome.

Test-only restrictions: one cooperating worker composition, no competing writers, no session-lock-loss fencing across independent M07 transactions, no production admission/revalidation, no automatic recovery of unconfirmed reservation intents, no certificate lifecycle or supervised production hosting. Capacity limit unchanged. Retain all existing validated V1/V2 and flow smoke tests. New smoke uses isolated actual trades and synthetic admission references. TLS is optional using the existing `QD_TEST_MTLS_DIRECTORY` test configuration, not established by this runner.
