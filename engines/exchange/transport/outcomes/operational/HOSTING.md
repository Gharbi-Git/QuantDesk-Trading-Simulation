# M06.12c.2 — operational hosting candidate

The ASP.NET Core-compatible Generic Host registration is disabled by default. It accepts a caller-owned V2 client and test DB connection string, verifies schema v1 and the authenticated/configured V4 journal status before starting, and never creates a binding or performs DDL. Explicit test-only opt-in to prepared dispatch is separate from recovery of already committed decisions. The service uses one nonpooled PostgreSQL session advisory lock (6061204) to exclude cooperating hosts. The existing per-operation lock (6061203) remains unchanged. A connection probe precedes each bounded pass. This is not a fencing token: a lock loss during a financial operation is still a production blocker, and manually invoked flows are not excluded by the host lease. Health reports the last successful pass, not zero backlog or overall trading readiness. Background pass faults stop the host; restart requires operator action. The health check is registered in DI, not mapped to HTTP. The host does not own the supplied client.

Run Test-ExchangeOperationalHosting.ps1 with Docker running and the existing V2 native executable. The real financial fixture provisions and cleans up its own test schema and journal; it refuses an existing schema. Plaintext loopback by default for isolated tests; if QD_TEST_MTLS_DIRECTORY is supplied, the existing fixture uses TLS. No new native dependencies. No changes to main API Program.cs, no live endpoints, no production connection strings or certificate management. Requires risk authorization, lock-loss fencing, journal lifecycle, production migrations and deployment configuration before integration into the primary API. The smoke intentionally injects an unauthorized command and expects a host fault; a log indicating that fault is normal only when the final PASS is present.
