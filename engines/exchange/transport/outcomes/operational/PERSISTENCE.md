# Operational C# persistence candidate

Adds a transaction-scoped Npgsql store for the previously tested schema. No replacement of V4 development dispatch or delivery. No player routes, runtime DDL, certificate changes or M07 mutations. The trusted future service must obtain authentic status and decisions, validate risk/admission and exact active M07 holds, and commit effects before checkpoint advancement. The store verifies wire shape and payload consistency, not receipt provenance or financial effects. Caller must commit or roll back transactions and avoid RPCs under locks; do not share connection or transaction across threads. A transaction must be rolled back on any failed operation. For real provisioning use reviewed migration and restricted deployment roles, not this smoke script. One epoch per database, no journal rollover yet. Smoke uses synthetic Protobuf decisions and simulated reservation/effects markers in quantdesk_test and rolls the entire schema back; no restart/commit crash test or actual trading. C# compilation and real PostgreSQL execution pending Windows validation.
